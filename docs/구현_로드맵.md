# 보호동물 추천 시스템 구현 로드맵

> 기준 시점: 2026-10-03
> 설계 기준: `docs/시스템_설계.md`
> 목적: 무엇을 어떤 순서로 수행하고, 무엇이 끝나야 다음 단계로 넘어가는지 관리한다.

이 문서는 시스템 개념을 다시 설명하지 않는다. 각 Phase의 입력, 실행 작업, 산출물, Gate와 다음 의사결정을 정의한다. Gate를 통과하지 못한 기능은 다음 단계에서 자동화되었다고 가정하지 않는다.

## Midterm Prototype Milestone

**시점:** 약 2~3주 뒤 중간발표
**관계:** 정식 Phase를 대체하지 않는 별도 시연 milestone
**목표:** 최종 시스템이나 추천 정확도를 완성하는 것이 아니라, **실제 데이터에서 프로젝트가 현실적으로 구현 가능하고 최소 추천 흐름이 실제로 동작함을 보여준다.**

### 목표 범위

1. RescueGroups 주요 target의 초기 feasibility 결과
2. PawInHand 주요 evidence가 실제 존재하는지에 대한 초기 exploratory audit
3. 소수 핵심 feature의 Feature Routing Matrix v0
4. 실제 PawInHand 동물 일부를 Animal Profile 형태로 구성
5. 간단한 User Profile 입력
6. 확인된 조건을 이용한 hard filtering
7. Weighted CBF baseline
8. 실제 후보에 대한 재현 가능한 Top-K 추천
9. Match와 Evidence Coverage 또는 정보 충분도의 분리 표시
10. `Unknown ≠ No`가 추천 결과와 Critical Unknown 표시에 반영되는 사례 시연

### Prototype 시연 흐름

```text
사용자 조건 입력
↓
실제 PawInHand 후보
↓
Hard filtering
↓
Weighted CBF
↓
Top-K
↓
추천 이유
+ Evidence 정보
+ 중요한 Unknown
```

중간발표에서는 추천 정확도, 장기 적합성 또는 최종 알고리즘의 유효성이 검증됐다고 주장하지 않는다. 다음을 실제 사례로 확인하는 데 목적이 있다.

- 실제 데이터와 필요한 evidence 일부가 존재한다.
- 소수 핵심 feature를 operational profile로 만들 수 있다.
- 사용자 조건과 동물 정보를 연결할 수 있다.
- 최소 추천 prototype이 실제 Top-K를 생성한다.
- 정보 부족을 단순 부정값으로 처리하지 않는다.

### 중간발표 완료 조건에 포함하지 않는 항목

- 전체 canonical feature 구현
- Phase 4 전체 Gold Set 완성
- Phase 5 전체 extraction model 비교
- 7B~7E 전체 고도화
- score/rank interval 정식 검증
- adaptive Dynamic Questioning
- LLM explanation
- Agent
- Learning-to-Rank
- 정식 user study
- 전체 robustness 실험
- 장기 입양 outcome

### 중간발표 이후 방향

Phase 1·2·3 결과와 prototype에서 발견된 문제를 바탕으로 Feature Extraction 정식 평가, Feature-wise Compatibility, Multi-Criteria Ranking, Evidence-aware Ranking, Robustness 중 실제 데이터에서 가치가 확인되는 고도화를 우선한다. 모든 고도화를 무조건 구현하지 않고, 근거와 일정에 따라 Final 범위를 선택한다.

## Phase 1 — RescueGroups target feasibility

**상태:** Next
**Priority:** P0
**Depends on:** Phase 0
**Can run in parallel with:** Phase 2
**Blocks:** Phase 3, Phase 4, Phase 5

### 목적

RescueGroups structured attributes가 실제 텍스트 feature extraction의 label 후보로 사용 가능한지 판단한다. coverage가 있다는 사실과 학습 label로 쓸 수 있다는 판단을 분리한다.

### 입력

- RescueGroups 종별 Parquet
- 전체 coverage와 distribution 결과
- canonical candidate schema
- RescueGroups field 정의 자료

### 작업

- description–target overlap을 계산한다.
- class distribution과 소수 클래스 수를 종별로 확인한다.
- dog/cat 간 coverage·label 분포 차이를 확인한다.
- organization별 missingness, target concentration, 기록 관행 차이를 확인한다.
- field의 label semantics와 값 생성 방식을 확인한다.
- `false`와 unknown 또는 기본값이 섞였을 가능성을 점검한다.
- 반복 문구와 template에 의한 lexical leakage를 점검한다.
- 조직·동물·문구 중복이 split을 넘는 leakage 가능성을 확인한다.

우선 대상:

- `activityLevel`
- `energyLevel`
- `exerciseNeeds`
- `newPeopleReaction`
- `isDogsOk`
- `isCatsOk`
- `isKidsOk`
- `isHousetrained`
- `ownerExperience`
- canonical schema와 직접 연결 가능한 기타 structured fields

### 산출물

`feature × RescueGroups usability matrix`:

| feature | species | text_overlap | class_balance | organization_bias | label_semantics | leakage_risk | usability |
|---|---|---:|---|---|---|---|---|

`usability` 값:

- `supervised_candidate`
- `weak_label_only`
- `verification_reference`
- `unusable`

### 완료 조건 Gate

- 모든 우선 target을 네 usability 상태 중 하나로 분류할 수 있다.
- 분류 이유가 overlap, 분포, semantics, missingness, leakage 근거와 연결되어 있다.
- supervised candidate로 분류된 target에 사용할 split 단위가 정해져 있다.
- 모델 학습은 아직 수행하지 않는다.

### 다음 단계에 미치는 결정

- `supervised_candidate`만 Phase 5의 supervised baseline 후보가 된다.
- `weak_label_only`는 noisy-label 또는 보조 실험으로 제한한다.
- `verification_reference`는 자동 target이 아니라 schema·질문 설계 근거로 보낸다.
- `unusable`은 현재 extraction 학습에서 제외하지만 canonical schema에서는 유지한다.

## Phase 2 — PawInHand evidence audit

**상태:** Next
**Priority:** P0
**Depends on:** Phase 0
**Can run in parallel with:** Phase 1
**Blocks:** Phase 3, Phase 4, Phase 6

### 목적

canonical Animal Profile 중 한국 추천 catalog의 실제 텍스트에서 명시적 evidence를 확보할 수 있는 항목을 확인한다.

### 입력

- PawInHand 현재 dataset
- `special_mark`
- 관리자 comment
- 상세 personality
- health 및 기타 실제 text fields
- canonical candidate schema와 evidence 상태 정의

### 작업

- 종별 target evidence coverage를 조사한다.
- 보호소별 기록량과 target 기록 편차를 조사한다.
- 텍스트 길이와 evidence availability의 관계를 확인한다.
- target별 문장을 `positive`, `negative`, `conditional`, `ambiguous`, `not-mentioned`로 구분한다.
- field별로 직접 구조화 가능한 값과 text extraction이 필요한 값을 분리한다.
- keyword hit는 탐색·표본화 보조로만 사용하고 최종 label로 사용하지 않는다.

이 분류는 PawInHand에 어떤 evidence가 실제 존재하는지 파악하기 위한 **exploratory audit**다. keyword, heuristic, LLM 등을 탐색·표본화 보조로 사용할 수 있으나 그 결과를 모델 평가용 gold label로 간주하지 않는다. 독립 gold label은 Phase 4의 annotation guideline과 모델·prompt 선택 전에 고정하는 test set에서 별도로 구축한다. Phase 2 산출물을 Phase 5 평가 정답으로 재사용하지 않아 circular evaluation을 방지한다.

### 산출물

- `feature × PawInHand evidence availability matrix`
- field별 evidence source map
- 보호소·종별 documentation bias 요약
- Phase 4 annotation을 위한 후보 표본 프레임

PawInHand 지원 상태:

- `direct_available`
- `text_extraction_required`
- `additional_verification_required`
- `currently_unavailable`

### 완료 조건 Gate

- 모든 canonical feature를 네 지원 상태 중 하나로 분류할 수 있다.
- 분류에 species, source field, evidence polarity와 ambiguity가 반영되어 있다.
- 명시 evidence가 거의 없는 feature를 자동 추정 대상으로 잘못 분류하지 않는다.

### 다음 단계에 미치는 결정

- Phase 3에서 RescueGroups 지원과 PawInHand 지원을 결합해 implementation route를 정한다.
- `additional_verification_required`는 Phase 8 질문·관찰 후보가 된다.
- `currently_unavailable`은 `unsupported` 또는 외부 evidence source 필요 후보가 된다.

## Phase 3 — Feature Routing Matrix 확정

**상태:** 대기
**Priority:** P0
**Depends on:** Phase 1, Phase 2
**Can run in parallel with:** Phase 6의 identity 설계 일부
**Blocks:** Phase 4, Phase 5, Phase 7

### 목적

문헌에서 도출한 canonical schema의 각 feature를 시스템이 어떤 방식으로 처리할지 결정한다. feature를 일괄 삭제하지 않고 route와 사용 역할을 명시한다.

### 입력

- RescueGroups usability matrix
- PawInHand evidence availability matrix
- 기존 논문·데이터 조사 근거
- SYSTEM_DESIGN의 feature family, uncertainty, hard/soft 원칙

### 작업

- feature와 species별 recommendation role을 정한다.
- RescueGroups support와 PawInHand support를 교차한다.
- implementation route를 부여한다.
- unknown, conflicting, conditional 값의 처리정책을 정한다.
- MVP에서 사용하는 feature와 Final 검증 후보를 구분한다.
- 한 feature가 source별로 다른 route를 갖는 경우 우선순위와 fallback을 명시한다.

### 산출물

최종 Feature Routing Matrix:

| feature | species | feature_family | recommendation_role | RescueGroups_support | PawInHand_support | implementation_route | uncertainty_policy | MVP_or_Final |
|---|---|---|---|---|---|---|---|---|

`implementation_route`:

- `direct`
- `ML extraction`
- `LLM extraction`
- `verification-only`
- `unsupported`

### 완료 조건 Gate

- 모든 canonical Animal Profile feature에 하나 이상의 명시적 route가 있다.
- 추천 점수에 들어가는 feature와 verification에만 쓰는 feature가 구분되어 있다.
- 근거가 없는 feature는 자동값이나 평균값으로 채우지 않는다.

### 다음 단계에 미치는 결정

- Phase 4의 annotation target과 Phase 5의 model candidate를 고정한다.
- Phase 6의 Profile/Evidence Store schema와 Phase 7의 scoring 입력을 확정한다.

## Phase 4 — Annotation / Gold Set 설계

**상태:** 대기
**Priority:** P0
**Depends on:** Phase 3
**Can run in parallel with:** Phase 6의 catalog·identity 작업
**Blocks:** Phase 5, Phase 11의 extraction 평가

### 목적

한국어 PawInHand text extraction을 독립적으로 평가할 기준을 모델 개발 전에 고정한다.

### 입력

- Feature Routing Matrix
- PawInHand 후보 표본 프레임
- target별 문헌 정의와 실제 한국어 표현 사례

### 작업

- annotation guideline을 먼저 작성한다.
- target definition과 종별 적용 범위를 정한다.
- `positive`, `negative`, `conditional`, `ambiguous`, `not-mentioned` 판정 기준을 작성한다.
- evidence span 표기 규칙을 정의한다.
- dog/cat, 보호소, 텍스트 길이, target 희귀성을 반영해 표본화한다.
- 가능한 범위에서 일부 표본을 이중 라벨링한다.
- disagreement resolution 절차와 label 변경 이력을 정한다.
- development set과 고정 test set을 분리한다.

### 산출물

- annotation guideline
- label schema와 예시집
- sampling plan
- 독립 gold test set
- inter-annotator agreement 및 disagreement 기록 형식

### 완료 조건 Gate

- annotator가 동일 문장을 일관된 기준으로 분류할 수 있다.
- test set이 모델·prompt 선택 전에 고정된다.
- test set 결과를 보며 target 정의를 반복 변경하는 leakage 방지 절차가 있다.

### 다음 단계에 미치는 결정

- Phase 5의 모든 baseline은 동일 test set과 label definition을 사용한다.
- 합의가 어려운 target은 assisted 또는 verification-only 후보로 재분류할 수 있다.

## Phase 5 — Feature Extraction Baselines

**상태:** 대기
**Priority:** P0
**Depends on:** Phase 4
**Can run in parallel with:** Phase 6의 Base Profile·Evidence Store 작업
**Blocks:** Phase 7의 자동 feature 사용, Phase 8, Phase 9

### 목적

어떤 방식이 text의 명시 evidence를 가장 안정적으로 구조화하는지 feature별로 비교하고 production route를 결정한다.

### 입력

- RescueGroups supervised/weak-label 후보
- annotation guideline과 PawInHand gold set
- Feature Routing Matrix

### 작업

최소 baseline을 비교한다.

1. simple rule / keyword baseline
2. conventional classifier 또는 pretrained text classifier가 가능한 경우의 baseline
3. 원문 evidence span을 요구하는 LLM structured extraction

RescueGroups에서는 organization-aware split과 species-aware evaluation을 사용한다. PawInHand 한국어 gold set은 외부 도메인 검증으로 분리한다.

### 산출물

- feature별 baseline 결과표
- 오류 유형과 evidence span 감사 결과
- route recommendation

평가:

- Precision
- Recall
- Macro-F1
- class별 F1
- abstention coverage와 수용 사례 성능
- evidence span correctness
- species·organization별 성능
- RescueGroups 내부 성능과 PawInHand 외부 성능 차이

### 완료 조건 Gate

## Phase 7 — Recommendation Baseline and Final Ranking Structure

**상태:** 대기
**Priority:** P0 + P1 분리. 7A와 7D 최소 기능은 P0, 나머지는 P1
**Depends on:** Phase 3, Phase 6. 자동 추출 반영은 Phase 5
**Can run in parallel with:** 없음
**Blocks:** Phase 8, Phase 9, Phase 10, Phase 11, Phase 12

### 목적

Weighted CBF를 deterministic non-Agent MVP baseline으로 고정하고, 그 위에 **Constraint-based + Multi-Criteria + Evidence/Uncertainty-aware Recommendation**을 단계적으로 구축한다.

Phase 7의 Final 구조는 유지하되 구현 우선순위는 다음처럼 구분한다.

- **P0:** 7A 전체와 7D 최소 기능
- **P1:** 7B, 7C, 7D 고급 기능, 7E
- P0 Gate 통과는 P1 전체 완료를 요구하지 않는다.

### 입력

- User Profile schema
- 추천 catalog와 Animal Profile
- Feature Routing Matrix
- hard/soft/verification 정책
- evidence와 uncertainty 상태

### 7A — Weighted CBF Baseline

**Priority:** P0

- User Profile 입력을 구성한다.
- hard constraints, soft preferences, care capacity를 분리한다.
- 확인된 hard violation만 filtering한다.
- weighted content-based scoring을 구현한다.
- 동일 입력에서 재현 가능한 Top-K와 template 근거를 생성한다.
- 이후 단계가 비교할 고정 baseline 결과와 평가 입력을 저장한다.

### 7B — Feature-wise Compatibility

**Priority:** P1

- feature별 scale, 방향성, 허용구간과 종별 의미에 맞는 compatibility function을 정의한다.
- nominal 조합표, ordinal/continuous 거리·threshold, capacity–requirement 비교를 구분한다.
- source가 없거나 충돌한 값은 0, 중립값, 평균으로 대체하지 않고 `unknown/conflicting`을 반환한다.
- 각 compatibility 결과를 source, 원문 evidence, 적용 함수·규칙까지 추적 가능하게 한다.

### 7C — Multi-Criteria Ranking

**Priority:** P1

- `preference`, `care_capacity`, `welfare_requirement`, `household_compatibility`를 별도 criterion family로 계산한다.
- 확인된 hard violation과 중대한 welfare/household conflict를 preference 가중치가 상쇄하지 못하는 non-compensatory gate를 구현한다.
- gate와 recommendation state를 먼저 적용하고 같은 상태 안에서만 soft criterion을 집계한다.
- 한 개의 불투명한 총점뿐 아니라 criterion별 scorecard와 순위 근거를 생성한다.

### 7D — Evidence/Unknown-aware Ranking

**Priority:** P0 최소 기능 + P1 고급 기능

P0 최소 기능:

- Match와 Evidence Coverage/Quality를 분리한다.
- unknown을 `No`, 0 또는 평균으로 대체하지 않는다.
- Critical Unknown과 `Ready / Needs information / Team review / Hold` 상태를 계산한다.
- 새 evidence를 입력할 수 있고 동일 recommendation pipeline을 재실행한다.

P1 고급 기능:

- 정당화 가능한 unknown 값 범위가 있을 때 score interval, 가능한 rank range 또는 pairwise rank uncertainty를 계산한다.
- 범위를 정할 근거가 없으면 임의의 수치 구간 대신 `rank unresolved`로 표시한다.
- 정보가 많은 동물이 자동으로 더 높은 적합 점수를 받지 않도록 evidence masking과 documentation bias를 점검한다.

### 7E — Robustness/Sensitivity Analysis

**Priority:** P1

- 사전에 정의한 합리적 범위에서 soft weight와 threshold를 변화시킨다.
- 순위 역전, Top-K 유지율, near-tie, 후보별 가능한 순위 범위를 측정한다.
- evidence masking과 unknown 시나리오에서 ranking robustness를 평가한다.
- 작은 weight 변화에 민감한 순위는 확정적 단일 순위로 제시하지 않고 민감 criterion을 함께 표시한다.
- LLM이나 semantic embedding이 최종 ranking, hard 또는 welfare 판정을 임의로 바꾸지 않는 구조를 유지한다. Semantic embedding은 natural-language parsing, evidence retrieval, candidate retrieval 보조로만 사용한다.

### 산출물

P0 산출물:

- deterministic recommendation pipeline
- 7A weighted CBF baseline 결과
- Top-K 결과 schema
- Match/Evidence 분리, Critical Unknown, 기본 recommendation state 산출 근거
- baseline template explanation

P1 산출물:

- feature별 compatibility function registry와 test cases
- criterion-family scorecard와 non-compensatory gate 명세
- score interval과 rank uncertainty 산출 근거
- weight sensitivity와 ranking robustness 결과

### 완료 조건 Gate

P0 Gate:

- 동일한 입력과 데이터 버전에서 동일 Top-K가 생성된다.
- 각 제외·점수·상태를 사용한 source와 규칙으로 설명할 수 있다.
- Match 표현이 장기 성공확률로 제시되지 않는다.
- Evidence Coverage가 Match와 분리되어 있다.
- unknown을 0이나 평균으로 대체하지 않는다.
- Critical Unknown과 기본 recommendation state를 표시할 수 있다.
- 새 evidence 입력 후 동일 pipeline을 다시 실행할 수 있다.

P1 Gate:

- 확인된 hard·welfare conflict가 preference 점수로 상쇄되지 않는다.
- feature별 compatibility와 criterion family별 결과를 역추적할 수 있다.
- score/rank uncertainty는 정당화 가능한 범위에서만 제시되고, 불가능한 경우 unresolved로 남는다.
- 합리적 weight 변화에 대한 순위 안정성 또는 민감성을 보고할 수 있다.

### 다음 단계에 미치는 결정

- Phase 8 이후의 모든 개선은 이 baseline과 동일 입력·후보셋에서 비교한다.

## Phase 8 — Uncertainty-aware Dynamic Questioning

**상태:** 대기
**Priority:** P1
**Depends on:** Phase 7의 P0 범위. 7D 고급 uncertainty 결과를 사용하려면 해당 P1 범위
**Can run in parallel with:** Phase 9의 평가 설계 일부
**Blocks:** Phase 10, Phase 11, Phase 12

### 목적

P0의 단순 unknown 표시·evidence update와 구분해, 여러 unknown 중 어떤 정보를 먼저 확인해야 순위·상태 불확실성이 가장 크게 줄어드는지 계산하고 다음 질문·확인 행동을 선택한다. Phase 8 전체 Priority는 P1로 유지한다.

### 입력

- 현재 User Profile과 Animal Evidence
- Critical Unknown
- hard/verification, care requirement, scoring 규칙
- 질문·관찰 후보와 가능한 답 상태

### 작업

rule-based decision sensitivity로 각 unknown을 확인했을 때 감소할 것으로 예상되는 **rank uncertainty와 recommendation-state uncertainty**를 계산한다. 다음 중 무엇을 얼마나 바꿀 수 있는지 비교한다.

- 후보 순위
- hard/verification 상태
- care requirement 충족 상태
- score interval 또는 가능한 rank range의 폭

rank/state uncertainty를 가장 크게 줄일 수 있는 unknown을 우선하되, 획득비용·소요시간·안전성과 실제 확인 가능성을 함께 고려한다. 영향이 있는 경우에만 사용자 질문, 보호소 질문, 관찰 제안을 선택한다. 가상 또는 실제 새 evidence를 입력하고 Profile과 Recommendation을 재계산한다. 학습형 AFA나 VOI라는 성능 주장은 하지 않는다.

### 산출물

- Critical Unknown prioritizer
- 질문별 예상 rank/state uncertainty 감소와 선택 근거
- 질문/확인 행동 목록
- evidence update와 re-ranking workflow
- 대표 scenario 시연 기록

### 완료 조건 Gate

대표 시나리오에서 다음 흐름을 재현할 수 있다.

```text
질문 또는 확인 제안
→ 새 Evidence 입력
→ Profile 갱신
→ 상태 또는 순위 변경
```

불필요한 질문을 모두 요구하지 않고, 선택 이유를 설명할 수 있어야 한다.

### 다음 단계에 미치는 결정

- 질문이 결과를 거의 바꾸지 않으면 해당 rule의 우선순위를 낮추거나 제거한다.
- 실제 획득 가능성이 낮은 정보는 질문 대신 담당자 확인 상태로 둔다.
