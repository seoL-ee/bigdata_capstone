# 추천 시스템 주제 후보 및 데이터·API 확보 방안 제안

## 1. 제안 배경

기존 반려동물 입양 추천 주제의 데이터 문제는 [PR #11](https://github.com/seoL-ee/bigdata_capstone/pull/11)과 [PR #12](https://github.com/seoL-ee/bigdata_capstone/pull/12)에서 검토되었습니다. 주요 쟁점은 성격·행동 정보의 부족과 편향, 사용자–동물 적합도 정답 부족, 추천 결과의 평가 기준입니다.

대안으로 다음 세 가지 주제를 제안합니다.

| 후보 | 주제 | 주요 데이터 | API 활용 목적 |
|---|---|---|---|
| 1 | 사용자 선호와 사용 조건을 반영한 반려동물 놀이·생활용품 추천 | Amazon Reviews 2023 | 네이버 쇼핑 검색을 통한 국내 상품 후보 조회 |
| 2 | 참여자 취향과 모임 조건을 반영한 보드게임 추천 | BGG 기반 평점·게임 상세 데이터 | BGG 게임 정보 조회·갱신 |
| 3 | 영상 편집 상황과 사용자 취향을 반영한 효과음 추천 | FSD50K, 공유마당, Kenney | Freesound 음원 검색·상세 정보 조회 |

데이터 설명은 공식 문서와 실제 파일·페이지에서 확인한 내용을 기준으로 합니다. 알고리즘과 서비스 구성은 구현 제안이며, 성능과 실제 활용도는 아직 검증되지 않았습니다.

## 2. 후보 1: 반려동물 놀이·생활용품 추천

### 2.1 주제 및 기능

사용자의 상품 선호와 반려동물 종류, 상품 크기, 사용 장소, 예산 등을 고려하여 놀이·생활용품을 추천합니다.

장난감, 스크래처, 하우스, 이동용품 등을 대상으로 다음 기능을 구성합니다.

- 상품 종류·가격·사용 목적에 따른 후보 선정
- 사용자 평점과 선택 기록을 반영한 개인화
- 상품 설명을 활용한 신규 상품 추천
- 추천 이유와 조건 충족 여부 제공

상품 조건 확인과 사용자 취향 예측을 구분하며, 건강·의료적 적합성 판단은 초기 범위에 포함하지 않습니다.

### 2.2 데이터 및 확보 방법

**주요 학습 데이터는 Amazon Reviews 2023의 `Pet Supplies`입니다.**

공식 통계상 약 780만 사용자, 49만 2,700개 상품, 1,680만 평점 기록이 포함됩니다. 상품 수는 리뷰에 등장하는 상품을 기준으로 하며 일부 상품에는 메타데이터가 없습니다. 전체 데이터셋은 2023년 9월까지의 상호작용 기록을 포함합니다. [공식 소개](https://amazon-reviews-2023.github.io/)

| 데이터 | 주요 필드 | 활용 |
|---|---|---|
| 리뷰 | 사용자 ID, 상품 ID, 평점, 본문, 시각 | 선호 학습 및 평가 |
| 상품 정보 | 상품 ID, 제목, 카테고리, 설명, 특징, 가격 | 상품 특징 표현 및 조건 반영 |

리뷰와 상품 정보는 `parent_asin`을 기준으로 연결합니다. 실제 표본에서 필드 구조를 확인했으며, 설명·특징·가격에 결측이 있었습니다. 전체 연결률과 결측률은 추가 집계가 필요합니다.

공식 다운로드 또는 Hugging Face 배포본을 이용하므로 **Amazon 상품 API 발급을 전제로 하지 않습니다.** 일정 수준 이상의 상호작용을 가진 사용자·상품을 남긴 5-core 가공본도 제공됩니다. 놀이·생활용품만 선별하면 기록이 줄어들므로 필터링 후 규모와 희소성을 다시 확인해야 합니다. [Hugging Face](https://huggingface.co/datasets/McAuley-Lab/Amazon-Reviews-2023), [5-core 안내](https://amazon-reviews-2023.github.io/data_processing/5core.html)

국내 상품 정보는 네이버 쇼핑 검색 API로 보완하는 방안을 검토합니다. 상품명·가격·브랜드·카테고리·링크 등을 제공하지만, 사용자별 구매·평점 기록은 제공하지 않습니다. 따라서 국내 상품 조회와 개인화 학습은 별도 데이터 확보 과제입니다. [공식 문서](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)

### 2.3 추천 및 평가 방안

인기 기반 모델을 기준으로 협업 필터링, 콘텐츠 기반 추천, 혼합 추천을 비교하고, 사용 조건을 반영한 재정렬을 추가합니다.

리뷰 시각을 활용하여 학습·검증·평가 데이터를 분리하고 Recall@K·NDCG@K 등을 비교합니다. 평가 시점 이후의 리뷰나 평가 대상 리뷰 본문이 학습 특징에 포함되지 않도록 구성합니다.

평점은 사용자 선호의 관측값입니다. 특정 반려동물에게 객관적으로 적합한 상품이라는 정답으로 해석하지 않습니다.

### 2.4 한계 및 보완 방안

| 한계 | 보완 방안 |
|---|---|
| 반려동물 특성 정보가 일관된 구조로 제공되지 않음 | 사용자가 입력한 조건과 명시적인 상품 정보를 비교 |
| 해외 과거 데이터와 국내 현재 상품의 차이 | 알고리즘 평가와 국내 적용 검증을 분리 |
| 국내 상품과 공통 식별자 부족 | 브랜드·모델·규격이 확인되는 범위에서 연결 후 검수 |
| 대상 범위를 좁히면 상호작용 감소 | 필터링 후 사용자·상품 수와 반복 평가 수 확인 |
| 상품 정보 결측 | 결측 처리 및 특징 조합별 성능 비교 |
| 이용·재배포 범위 미확정 | 배포처 조건 확인 후 원본 데이터 공개 범위 결정 |

## 3. 후보 2: 모임 조건을 반영한 보드게임 추천

### 3.1 주제 및 기능

참여자별 게임 취향과 모임 인원, 플레이 시간, 난이도를 고려하여 보드게임을 추천합니다.

개인별 선호 점수를 예측한 뒤 그룹 단위로 결합합니다. 평균 선호를 높이는 방식과 특정 참여자의 낮은 선호를 완화하는 방식 등을 비교합니다.

주요 기능은 다음과 같습니다.

- 모임 인원·시간·난이도에 따른 후보 선정
- 참여자별 초기 선호 입력
- 그룹 선호를 반영한 순위 제공
- 게임 특징과 추천 이유 표시

### 3.2 데이터 및 확보 방법

BGG 자료를 바탕으로 공개된 다음 CSV의 일부를 확인했습니다.

| 파일 | 확인한 주요 필드 |
|---|---|
| `bgg-26m-reviews.csv` | 사용자, 평점, 댓글, 게임 ID, 게임명 |
| `games_detailed_info2025.csv` | 게임 ID, 설명, 인원, 시간, 연령, 분류, 메커니즘, 난이도, 투표 정보 |

표본에서는 게임 ID로 평점과 상세 정보를 연결할 수 있었습니다. 다만 전체 행 수, 평점 분포, 중복, 전체 연결률은 아직 검증하지 않았습니다. [공개 데이터 배포 페이지](https://www.kaggle.com/datasets/jvanelteren/boardgamegeek-reviews)

인원·시간은 후보 필터링에, 설명·분류·메커니즘은 콘텐츠 기반 추천에 활용할 수 있습니다. 평균 난이도와 인원별 추천 투표는 이용자 평가 집계이므로 절대적인 기준으로 취급하지 않습니다.

공개 CSV를 활용한 초기 실험과 BGG API를 통한 정보 갱신은 구분합니다. 공개 CSV 다운로드를 위해 BGG API 토큰을 발급받는 구조는 아닙니다.

국내 적용 시에는 한글명·판본·확장판과 게임 ID의 대응이 필요하며, 전체 자동 연결은 검증되지 않았습니다.

### 3.3 추천 및 평가 방안

| 단계 | 비교 방법 |
|---|---|
| 개인 추천 | 인기 기반, 협업 필터링, 콘텐츠 기반, 혼합 추천 |
| 그룹 추천 | 개인 점수 평균, 최저 점수 고려, 두 기준의 절충 |
| 조건 반영 | 인원·시간·난이도 필터링 |
| 평가 | 개인 추천 정확도, 그룹 평균 선호, 참여자 간 선호 차이 |

확인한 평점 파일에는 시각 필드가 없습니다. 사용자별 기록 분할을 검토하되 시간 순서에 따른 평가가 아니라는 한계를 명시합니다.

가상 그룹 평가는 추천 방식의 특성을 비교하는 데 사용하고, 실제 모임 만족도는 별도 사용자 실험으로 확인합니다. 개인 평점의 합성 결과를 실제 그룹 만족도의 정답으로 사용하지 않습니다.

### 3.4 한계 및 보완 방안

| 한계 | 보완 방안 |
|---|---|
| 모임 단위 만족도 기록 부족 | 가상 그룹 평가와 실제 그룹 평가 분리 |
| BGG 이용자와 국내 초보자의 차이 가능성 | 국내·초보 이용자 대상 별도 평가 |
| 평점 시각 정보 부재 | 사용자별 분할과 중복 방지 적용 |
| 국내 이름·판본 연결 문제 | 기본판 중심으로 범위를 정하고 대응표 검수 |
| 신규 사용자 이력 부족 | 익숙한 게임에 대한 선호 입력 |
| 전체 품질·이용 조건 미검증 | 전체 분포·연결률 및 이용 범위 확인 |

## 4. 후보 3: 영상 편집 상황을 반영한 효과음 추천

### 4.1 주제 및 기능

효과음을 삽입할 장면과 분위기·길이를 입력받아 음원을 추천하고, 선택·선호 기록을 반영하여 순위를 조정합니다.

핵심 기능은 장면 설명 입력, 효과음 추천, 미리 듣기, 선호 피드백, 출처·라이선스 표시입니다. 영상 자동 편집은 초기 범위에 포함하지 않습니다.

### 4.2 데이터 및 확보 방법

FSD50K는 Freesound 음원을 바탕으로 구성된 소리 분류 데이터셋입니다. 공식 파일에서 고유 음원 51,197개의 메타데이터와 라벨 연결을 확인했습니다.

| 정보 | 내용 |
|---|---|
| 메타데이터 | 제목, 설명, 태그, 업로더, 라이선스 |
| 라벨 | 음원에 포함된 소리 종류 |
| 사용자 선호 기록 | 확인한 배포 파일에는 없음 |
| 영상 장면 적합도 | 정답 데이터 없음 |

소리 분류 라벨과 사용자 선호는 구분해야 합니다. 편집용 길이·품질과 음원별 이용 조건도 별도로 확인해야 합니다. FSD50K는 공식 배포 파일을 내려받는 방식이므로 Freesound API 키가 필수는 아닙니다. [공식 배포](https://zenodo.org/records/4060432)

추가 출처는 다음과 같습니다.

| 출처 | 확인 내용 | 적용 시 제한 |
|---|---|---|
| 공유마당 | 한국어 설명·태그·이용 조건, 실제 CC BY 효과음 | 전체 규모·자동 수집 미검증 |
| Kenney | Interface Sounds 100개, CC0 | 개별 설명과 다양성 추가 확인 |
| Mixkit·Pixabay | 편집용 효과음 | 원본 음원 재배포 제한 |
| ZapSplat | 다양한 효과음 | 무료 다운로드 제한·출처 표시 조건 |
| 효과음 랩 | 연출·버튼 소리 | 효과음 재생·삽입 앱 등에 대한 재배포 제한 |
| YouTube 오디오 보관함 | 영상용 효과음 | 별도 서비스 수집·재배포 범위 미확인 |
| Sonniss | 무료 오디오 묶음 | 현재 AI·ML 학습 금지 안내로 학습 후보에서 제외 |

이 사이트들은 현재 제안에서 모두 API 연동 대상으로 확정된 것은 아닙니다. 무료 영상 사용 허용과 자동 수집·학습·재배포 허용을 구분합니다.

### 4.3 추천 및 평가 방안

키워드 검색을 기준으로 텍스트 의미 기반, 오디오 기반, 혼합 추천을 비교하고 사용자 피드백을 활용한 개인화를 추가합니다.

여러 평가자의 장면–음원 적합도 판단을 수집하여 추천 품질을 평가합니다. 실제 활용도는 기존 검색 대비 선택 시간, 청취 횟수, 선택 여부, 만족도로 비교합니다.

복수의 적합한 음원을 허용하고 평가자 간 의견 차이를 기록합니다. 직접 수집한 피드백은 학습과 최종 평가에 중복 사용하지 않습니다.

### 4.4 한계 및 보완 방안

| 한계 | 보완 방안 |
|---|---|
| 사용자 선호 기록 부족 | 콘텐츠 기반으로 시작하고 직접 피드백 수집 |
| 장면 적합도 정답 부재 | 다수 평가자의 판단과 평가 일치도 확인 |
| 실제 수요 미검증 | 편집 경험자 대상 예비 조사 |
| 음원별 이용 조건 차이 | 사용 가능한 자료 선별 및 출처 관리 |
| 음질·설명 품질 편차 | 정제·중복 점검·표본 청취 |
| 평가 자료 구축 부담 | 편집 상황과 음원 범위를 제한 |

## 5. API 신청 및 인증 방법

현재 API 키 발급, BGG 애플리케이션 승인, 인증된 시험 호출은 수행하지 않았습니다. 아래는 공식 안내에 따른 신청 경로입니다.

### 5.1 네이버 쇼핑 검색 API

**용도:** 국내 상품 후보 및 상품 정보 조회

**신청 절차**

1. 네이버 계정으로 개발자센터에 로그인합니다.
2. `Application → 애플리케이션 등록`으로 이동합니다.
3. 이용약관 동의와 최초 휴대폰 인증 등 계정 정보 등록을 진행합니다.
4. 애플리케이션 이름, 검색 API, 서비스 환경 정보를 입력합니다.
5. 등록 후 `내 애플리케이션`에서 Client ID와 Client Secret을 확인합니다.

공식 일반 등록 절차에는 사업자등록증이나 기업 제휴가 요건으로 명시되어 있지 않습니다. 다만 계정 정보의 회사 이름 등 입력 항목은 실제 신청 화면에서 확인해야 합니다. [등록 안내](https://developers.naver.com/docs/common/openapiguide/appregister.md)

**인증 및 제한**

| 항목 | 내용 |
|---|---|
| 인증 | 요청 헤더에 Client ID·Client Secret 전달 |
| 일일 호출 한도 | 25,000회 |
| 요청당 결과 | 최대 100개 |
| 검색 시작 위치 | 최대 1,000 |
| 제공하지 않는 데이터 | 사용자별 구매·평점·리뷰 이력 |

전체 국내 상품을 제한 없이 내려받는 API가 아니므로 검색어별 후보 조회를 중심으로 활용합니다. [쇼핑 검색 문서](https://developers.naver.com/docs/serviceapi/search/shopping/shopping.md)

### 5.2 BGG XML API

**용도:** 게임 상세 정보 조회·갱신

**신청 절차**

1. BGG 계정을 생성하거나 로그인합니다.
2. [Applications](https://boardgamegeek.com/applications)에서 애플리케이션을 생성합니다.
3. 사용 목적 등 요구되는 정보를 제출합니다.
4. 애플리케이션 승인을 확인합니다.
5. 승인된 애플리케이션의 `Tokens`에서 토큰을 생성합니다.
6. API 요청에 `Authorization: Bearer <토큰>` 헤더를 포함합니다.

공식 안내상 **승인된 애플리케이션이 있어야 토큰을 생성할 수 있습니다.** 따라서 즉시 발급이나 승인 소요 시간을 보장하지 않습니다. 사용량은 애플리케이션의 `Usage`에서 확인하며, 적용 한도는 라이선스에 따라 달라질 수 있습니다. [공식 이용 안내](https://boardgamegeek.com/using_the_xml_api)

공개 CSV를 이용한 초기 실험은 API 승인 절차와 분리하여 준비할 수 있습니다. 다만 공개 데이터와 API 데이터 각각의 이용 조건은 확인해야 합니다. [API 이용약관](https://boardgamegeek.com/wiki/page/XML%20API%20Terms%20of%20Use)

### 5.3 Freesound API

**용도:** 효과음 검색, 설명·태그·라이선스 조회, 미리 듣기 정보 확보

**신청 절차**

1. Freesound 계정을 생성하고 로그인합니다.
2. [API 신청 페이지](https://freesound.org/apiv2/apply/)에서 API credential을 신청합니다.
3. 로그인 후 표시되는 요구 정보를 입력하고 이용 조건을 확인합니다.
4. 발급된 API 키를 기본 검색·조회 요청에 사용합니다.

신청 페이지는 로그인이 필요하므로 로그인 이후의 전체 입력 항목과 실제 발급 소요 시간은 확인하지 않았습니다.

**인증 방식 구분**

| 작업 | 인증 |
|---|---|
| 기본 검색·상세 정보 조회 | API 키 |
| 미리 듣기 파일 이용 | 공식 안내상 OAuth2 불필요 |
| 원본 음원 다운로드 | OAuth2 필요 |

원본 다운로드를 구현할 경우, 애플리케이션에 대한 사용자 승인 후 인증 코드를 액세스 토큰으로 교환하는 OAuth2 절차를 추가합니다. 기본 API 키만으로 원본 다운로드까지 가능하다고 가정하지 않습니다. [인증 문서](https://freesound.org/docs/api/authentication.html)

**기본 호출 제한**

- 일반 요청: 분당 60회, 하루 2,000회
- 원본 다운로드 등 일부 요청: 분당 30회, 하루 500회

미리 듣기와 원본 음원은 품질·형식이 다를 수 있으므로 오디오 분석에 사용할 버전을 일관되게 정해야 합니다. [API 개요 및 제한](https://freesound.org/docs/api/overview.html)

API는 비상업적 이용에 대해 무료로 제공되며, 상업적 이용은 별도 조건이 적용됩니다. API 사용 조건과 개별 음원의 라이선스는 별개로 확인합니다. [API 이용 조건](https://freesound.org/docs/api/terms_of_use.html)

### 5.4 API 발급이 필수인 자료와 아닌 자료

| 출처 | 현재 제안에서의 확보 방식 | API 발급 필요 여부 |
|---|---|---|
| Amazon Reviews 2023 | 공식 배포 파일 다운로드 | Amazon API 불필요 |
| BGG 기반 Kaggle 데이터 | 공개 CSV 다운로드 | BGG API 불필요 |
| FSD50K | Zenodo 배포 파일 다운로드 | Freesound API 불필요 |
| 네이버 쇼핑 검색 | 인증된 API 요청 | 필요 |
| BGG 최신 정보 | 승인된 API 요청 | 필요 |
| Freesound 실시간 검색 | 인증된 API 요청 | 필요 |
| 공유마당·Kenney | 자료별 다운로드 경로 검토 | 현재 API 연동을 전제로 하지 않음 |
| 기타 효과음 사이트 | 이용 조건 및 수집 가능성 검토 | 사용 가능한 API 확보 미확정 |

Hugging Face·Kaggle의 다운로드 도구를 사용할 경우 플랫폼 인증이 필요할 수 있으나, 이는 원본 서비스의 데이터 API 발급과 구분합니다. LLM API는 세 후보의 필수 구성 요소로 두지 않습니다.

API 비밀키와 토큰은 코드·PR에 포함하지 않고 실행 환경에서 관리합니다.

## 6. 후보 비교 및 선정 전 검증

| 항목 | 반려동물 용품 | 보드게임 | 효과음 |
|---|---|---|---|
| 기존 사용자–항목 기록 | 평점·리뷰 | 사용자별 평점 | 확인한 주 데이터에는 없음 |
| 기본 추천 평가 | 상품 선호 예측 | 개인 게임 선호 예측 | 평가 자료 직접 구축 필요 |
| 추가 평가 | 조건 반영·국내 적용 | 실제 그룹 만족도 | 장면 적합도·검색 대비 효용 |
| 핵심 실험 | 협업·콘텐츠·조건 결합 | 개인 선호의 그룹 결합 | 텍스트·오디오·개인화 결합 |
| API 의존성 | 국내 상품 조회에 활용 | 최신 정보 갱신에 활용 | 실시간 검색·추가 확보에 활용 |

주제 확정 전에는 다음 사항을 확인합니다.

1. 대상 범위의 실제 데이터 규모, 결측, 중복 및 연결률
2. 데이터의 학습·저장·서비스 제공·재배포 조건
3. 필요한 API의 발급·승인과 최소 시험 호출
4. 기존 기록으로 평가할 범위와 직접 평가 자료를 구축할 범위
5. 한 학기 내 구현·비교 실험이 가능한 핵심 기능 범위

본 문서는 주제 선정을 위한 데이터·구현·평가 방안 제안이며, 최종 주제와 범위는 추가 검증 및 팀 논의를 통해 결정하고자 합니다.
