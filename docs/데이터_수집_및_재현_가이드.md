# 데이터 수집 및 재현 가이드

## 1. 목적

본 프로젝트에서 사용하는 외부 데이터의 저장·공유·재현 방식을 통일한다.

특히 RescueGroups API 데이터는 원본 데이터를 저장소에서 공유하는 대신,
각 팀원이 자신의 API Key와 동일한 수집 코드를 이용해 필요한 데이터를
로컬에서 재생성하는 방식을 기본으로 한다.

## 2. 기본 원칙

- GitHub에는 수집·전처리·분석 코드와 실행 방법을 저장한다.
- API Key 및 `.env` 파일은 Git에 올리지 않는다.
- RescueGroups의 raw JSON과 processed Parquet는 Git에 올리지 않는다.
- 각 팀원은 자신의 RescueGroups API Key를 사용한다.
- 데이터가 필요할 경우 저장소의 동일한 수집 코드를 실행해 로컬에서 생성한다.
- API-derived row-level 데이터는 기본적으로 팀 저장소에서 공유하지 않는다.
- 분석에 사용한 기준 snapshot은 manifest로 식별한다.

## 3. RescueGroups 데이터 재현 흐름

git clone
↓
개인 `.env` 생성 및 API Key 입력
↓
RescueGroups 수집 script 실행
↓
raw JSON 생성
↓
전처리 script 실행
↓
Parquet 및 분석용 데이터 생성
↓
분석 script 실행

구체적인 명령어는 실제 repository 구조와 CLI를 기준으로 작성한다.

## 4. Git에 포함하는 항목

- 데이터 수집 코드
- 데이터 전처리 코드
- 분석 코드
- `requirements.txt`
- `.env.example`
- `.gitignore`
- 실행 방법
- 데이터 schema 설명
- snapshot manifest 등 재현에 필요한 metadata
- 공개 가능한 집계 결과

## 5. Git에 포함하지 않는 항목

- `.env`
- API Key
- RescueGroups raw JSON
- processed Parquet
- 개별 동물 단위 API record
- 원문 description이 포함된 row-level sample
- 기타 API 원자료를 사실상 재배포하는 파일

## 6. Snapshot과 재현성

RescueGroups API는 시점에 따라 등록·수정·삭제되는 live dataset이므로,
다른 시점에 다시 수집한 데이터가 기존 snapshot과 완전히 동일할 것을 보장하지 않는다.

따라서 본 프로젝트에서의 재현성은 다음 두 가지를 구분한다.

### 절차 재현성
동일한 코드와 설정을 이용하여 동일한 수집·전처리·분석 절차를 다시 실행할 수 있음.

### 실험 Snapshot 재현성
발표·보고서·실험에 실제 사용한 데이터는 수집 시점과 manifest를 통해 별도로 식별함.

manifest에는 가능한 범위에서 다음 정보를 기록한다.

- 수집 시작/종료 시각
- 데이터 source
- species
- API endpoint/version
- 주요 request parameter
- raw record count
- unique record count
- duplicate count
- 생성 파일 정보
- 가능하면 file hash
- 사용한 code commit

## 7. 팀원 간 데이터 사용

RescueGroups 데이터는 기본적으로 각 팀원이 직접 재수집한다.

수집 시간이 짧고 팀원 모두 개인 API Key를 보유하고 있으므로,
Google Drive 등에 원본 snapshot을 상시 공유하지 않는다.

향후 특정 실험에서 완전히 동일한 frozen snapshot을 여러 팀원이 사용해야 할
필요가 생기면 해당 시점에 별도 공유 방법과 이용조건을 다시 검토한다.

## 8. 다른 데이터

PawInHand, 국가동물보호정보 API, 연구용 공개 데이터셋 등은
각 source의 이용조건과 현재 프로젝트의 데이터 관리 방식을 별도로 적용한다.

RescueGroups의 관리정책을 다른 데이터 source에 자동으로 동일 적용하지 않는다.
